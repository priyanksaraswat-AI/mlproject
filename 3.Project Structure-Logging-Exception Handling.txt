## CustomException class

```python
class CustomException(Exception):
```

**Purpose:** Creates your own custom exception class.

It inherits from Python's built-in `Exception` class.

So instead of simply getting:

```text

```

you can get additional information such as:

```text
File name
Line number
Actual error
```

## Overall flow

Think of the code like this:

```text
An error occurs
      ↓
CustomException is called
      ↓
error_message_detail()
      ↓
Find Python file name
      ↓
Find line number
      ↓
Get original error
      ↓
Create detailed message
      ↓
Store it in self.error_message
      ↓
__str__() returns the detailed message
```

### Example

Suppose this code:

```python
try:
    x = 10 / 0
except Exception as e:
    raise CustomException(e, sys)
```

causes an error.

Instead of only:

```text
ZeroDivisionError: division by zero
```

your custom exception can provide:

```text
Error occurred in python script name [test.py]
line number [2]
error message [division by zero]
```

**In an ML project, the main benefit is debugging:** when a pipeline fails, you immediately know **which file, which line, and what error occurred**.

1. Import required libraries
import logging

Purpose: Imports Python's built-in logging module.
It allows us to record information such as INFO, WARNING, and ERROR.

import os

Purpose: Provides functions for working with files, folders, and operating-system paths.

We use it to create the logs folder and construct the log-file path.

from datetime import datetime

Purpose: Imports datetime so we can generate the current date and time.

We use it to create a unique log filename.

2. Create the log filename
LOG_FILE = f"{datetime.now().strftime('%m_%d_%Y_%H_%M_%S')}.log"

Purpose: Creates a filename based on the current date and time.

For example:

09_21_2026_15_30_45.log

Breaking it down:

datetime.now() → gets current date/time.
.strftime() → converts date/time into the specified format.
%m → month
%d → day
%Y → year
%H → hour
%M → minute
%S → second
.log → log-file extension.

The f before the string is an f-string, allowing us to insert the generated date/time into the filename.

3. Create the logs folder path
logs_path = os.path.join(os.getcwd(), "logs")

Purpose: Creates the path where log files will be stored.

os.getcwd() → gets the current working directory.
"logs" → specifies a folder named logs.
os.path.join() → safely combines them.

For example:

E:\KN-ML\Project\logs
4. Create the logs directory
os.makedirs(logs_path, exist_ok=True)

Purpose: Creates the logs folder if it doesn't already exist.

exist_ok=True means:

If the folder already exists, don't generate an error.

5. Create the complete log-file path
LOG_FILE_PATH = os.path.join(logs_path, LOG_FILE)

Purpose: Combines the folder path and filename.

For example:

E:\KN-ML\Project\logs\09_21_2026_15_30_45.log
6. Configure the logging system
logging.basicConfig(

Purpose: Configures how Python's logging system should behave.

    filename=LOG_FILE_PATH,

Purpose: Tells Python where to save the log messages.

Instead of displaying logs only in the terminal, they are written to the specified .log file.

    format="[ %(asctime)s ] %(lineno)d %(name)s - %(levelname)s - %(message)s",

Purpose: Defines the format of each log entry.

For example:

[ 2026-09-21 15:30:45,123 ] 25 logger - INFO - Logging has started.

The placeholders mean:

Placeholder	Meaning
%(asctime)s	Date and time of the log
%(lineno)d	Line number where logging occurred
%(name)s	Name of the logger
%(levelname)s	Log level
%(message)s	Actual message
    level=logging.INFO,

Purpose: Sets the minimum logging level to INFO.

Python logging levels generally work like:

DEBUG
INFO
WARNING
ERROR
CRITICAL

With level=logging.INFO, the logger records:

INFO
WARNING
ERROR
CRITICAL

but normally ignores DEBUG.

)

Purpose: Closes the logging.basicConfig() configuration.
